## Next sequence

1. Review connector-specific dependencies and verify selected vendor authentication with explicitly authorized source access. Native SQLite and selected loopback REST/GraphQL checks have passed; keep their evidence separate from authenticated vendor use.
2. Measure a new user's configure → sync → bootstrap → query → refresh experience on their own tools, including credential setup, source permissions and required business-definition review.
3. Validate approved own-tool use with design partners and a real Registry consumer/update round trip. No source data or artifacts are published automatically.
4. Resume comparative evaluations only when requested. The existing Rystic pilot and held-out study contracts remain deferred; their evidence and accounting requirements still apply before performance claims.

The core can be tried without Rystic or an Atlan account. The live comparative phase requires an available Rystic runtime and an explicitly bounded model run. Offline tests and pre-registration artifacts do not substitute for that measurement.

The controller's measured runtime starts after offline protocol/input validation and runtime construction, and stops before final statistical reporting and export. This analysis overhead is excluded and unmeasured; it is not a measured zero. Complete billing reconciliation, including an explicit treatment of these exclusions, remains required before any all-in claim. The controller and standalone acceptance-report replay enforce this by retaining `charter_ready: false` for unreconciled runs while preserving their separate statistical results.

The [sequential collection design](sequential-study.md) records the required order, provisioning boundary, remaining acceptance contracts and accounting decisions.

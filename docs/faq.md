# Questions before you start

## Who is this for?

Analytics engineers, AI engineers and technical operators who already use an agent and want to answer recurring questions across business tools. The current interface is a local CLI, with optional agent access. A business stakeholder can help define the question and review the policy; the initial setup needs someone comfortable with files, SQL and source permissions.

## Can I use any tool?

Bring supported exports from any tool that can provide them, or use an available adapter. The catalog contains 101 source definitions across APIs, databases, files and object stores. That is coverage of definitions, not 101 authenticated production integrations. Check `source describe TOOL` and `source doctor TOOL` before choosing a path. [Connector setup](connectors.md).

## Is this ready for production?

This is a developer preview. Local file workflows, SQLite and selected local REST/GraphQL fixtures have end-to-end verification. Live vendor authentication, wider client interoperability and own-data adoption still need validation. There is no hosted service, managed OAuth, scheduler or production authorization boundary. [Current evidence](build-status.md).

## Do I need a model or registry account?

No. Import, bootstrap, SQL, metrics and bundle export work locally. The quickstart has no model calls. Natural-language `ask` uses a separately authenticated Claude CLI; a compatible MCP client can use its own configured model. A registry account is not required to create or inspect a local context bundle.

## Why do some files still say `contextbase`?

Oriel is the product and CLI name. The internal Python module, database metadata namespace and versioned formats retain the working name `contextbase` for compatibility. Paths such as `contextbase/`, `python -m contextbase` and serialized identifiers such as `contextbase.metrics/...` therefore remain valid. Historical receipts and generated evidence were not regenerated by the rebrand; their original names and hashes are preserved.

## Where does my data go?

Imports, SQL, profiling and bootstrap operate in your local workspace. Source sync contacts the configured service to retrieve data. Built-in `ask --allow-model-data` sends the question, context and relevant tool results to the configured model; an MCP client may also send results to its model. A local DuckDB file does not make model inference local.

Source configurations store credential environment-variable references. Supply values through your approved environment or secret-injection mechanism. The workspace contains imported data and retained extraction artifacts, so protect it accordingly. Bundle export performs no network upload; although it excludes table rows and credentials, its schemas, SQL and business rules can be sensitive. [Agent data boundaries](agents.md).

## Does bootstrap figure out what my metrics mean?

It drafts observations about schema, keys, joins and unresolved questions. It does not infer authoritative definitions of revenue, activation or pipeline. Metric proposals need SQL and explicit business declarations, then exact-version review. [Context guide](context-guide.md).

## Does refresh update everything automatically?

No. Run `source sync NAME` explicitly for a configured connection, or `ingest --replace` for a selected imported table. Connector publication is atomic within that connection. Independent source syncs do not create a transactionally consistent snapshot across services. Materialized `models.*` transformations do not automatically recompute.

A failed connector extraction preserves the prior snapshot. Check `source list`: the latest attempt and last published snapshot are separate, so preserved data must not be mistaken for current source state. Approved definitions survive refresh; changed business meaning requires a new review.

## Can my agent change Salesforce, billing records or tickets?

The agent-facing question loop and MCP tools are read-only. CLI transformations create local tables; exact-preview row changes affect only the local workspace. There is no live source writeback. The [complete export recipe](tool-exports.md) demonstrates reviewed local mapping changes.

## How does this relate to MCP?

Oriel supports MCP as an agent interface. Its architectural choice is to compute over a DuckDB snapshot and make business definitions reusable. An MCP server can expose source records, source-side aggregates or SQL; those are different data paths over the same protocol. Comparative accuracy, cost and speed evaluations are deferred, so no superiority claim is established.

## How does this differ from a warehouse or a semantic layer?

The starting point is a small local workspace for an existing question. You can inspect imported data, review a definition and export the resulting context without provisioning a shared service. A production warehouse, semantic layer or registry may provide organizational capabilities beyond this preview. Oriel's local approval and bundle handoff do not substitute for team identity, permissions or distribution.

## What if setup fails?

| Symptom | Check |
| --- | --- |
| Python version rejected | Use Python 3.10–3.14, matching `pyproject.toml`. |
| `.venv/bin/oriel` is missing | Run `uv sync --frozen` from the repository root. POSIX examples need WSL or adjusted executable paths on Windows. |
| Frozen install cannot access package artifacts | The lock uses public PyPI artifacts. Check access to PyPI and its artifact host, your Python version and your organization's package policy. Report a sanitized error; do not share credentials. |
| Connector dependency missing | Install the declared extra with `uv sync --frozen --extra connectors`, then inspect `source doctor TOOL`. Additional SDKs or drivers are source-specific. |
| The extra disappeared after another command | Use `.venv/bin/oriel`, or keep `--extra connectors` on `uv run`. |
| A credential reference is unavailable | Supply the named variable to the extraction process; do not put its value in source JSON or an issue. |
| A table already exists | Use a new workspace for a repeated tutorial. Use `ingest --replace` only when you intend to replace that table. |
| Sync failed but queries still return rows | Inspect `source list`; you may be reading the last successful snapshot. |
| Metric approval is stale | Regenerate the proposal and review its SQL, data witness and exact hash again. |
| A query reaches its row limit | Narrow or aggregate the query; inspect truncation before treating the result as a complete population. |

Use a synthetic reproduction in a public issue. Include the command with sensitive values removed, Python/package versions, expected behavior and the observed error. Never post credentials, private source records or a data-bearing workspace.
